7B는 원출력 `kg3`, `개4`의 표시 순서만 정리했으며 숫자는 바꾸지 않았습니다. 반복 시험에서 이미지 한 장당 실행 시간은 약 **19~33초**였습니다. 정확도는 통과했지만 사용자가 파일 크기를 이유로 제외하여 삭제했습니다.

검증 조건: macOS Apple Silicon, llama.cpp `b11284`, CPU만 사용, 추론·입력 처리 각 2개 스레드. 텍스트 모델은 Apple Vision OCR과 영수증 열 복원 결과를 입력받았고, Qwen3-VL은 원본 이미지를 직접 입력받았습니다. AI 검증에서는 규칙 계산의 정답을 모델 답으로 대체하지 않았습니다.

시험 중 프롬프트, 입력 열 선택, 출력 처리, 토큰 한도를 수정했습니다. 이 표는 **동일 조건의 성능 순위가 아닌 실제 실행 기록 요약**입니다. 자동 채점은 간결한 숫자·단위 형식을 요구하므로 `총 4개`, `**4개**`, 불필요한 콜론 등은 형식 검사에서 탈락할 수 있습니다. 표에서는 답의 내용과 형식 문제를 구분했습니다. 한 번 정답을 낸 것은 반복 검증 성공과 구분하며, 다른 문제의 정확도를 보장하지 않습니다.

화면을 한 번 캡처한 이미지에서 글자를 추출하고 기초 문제를 푸는 작은 macOS 앱의 첫 버전입니다. Swift/AppKit과 Apple Vision만 사용하며, 웹뷰·서버·패키지 다운로드·원격 API·분석 로그가 없습니다.

## 시작

```sh
cd /Users/tei/OfflineLens
sh scripts/build.sh
open 'dist/Offline Lens.app'
```

macOS 13 이상과 Apple Command Line Tools가 필요합니다. 한국어 OCR 지원 여부는 실행 시 확인합니다. 외부 Swift 패키지 의존성이 없어 개발 도구가 설치되어 있으면 빌드도 오프라인입니다.

1. 크롬 등 원하는 화면을 띄우고 **메뉴 막대의 카메라 아이콘**을 누릅니다. 다른 앱을 앞으로 가져오지 않고, 마우스가 있는 모니터에 실제로 보이는 화면 전체를 PNG 한 장으로 캡처합니다. 창이 겹쳐 있으면 그 모습대로 찍히며, 가려진 내용이나 스크롤 밖의 내용은 포함하지 않습니다. 영역 선택이나 파일 첨부는 필요 없습니다. 앱의 **지금 보이는 화면 캡처** 버튼 또는 앱이 활성화된 상태에서 `⌘⇧S`도 사용할 수 있습니다. Offline Lens 창은 캡처 직전에 잠시 숨기고 완료 후 다시 표시합니다. 전역 키보드 감시는 하지 않습니다.
2. OCR 결과를 확인하고 틀린 글자·수량·금액을 수정합니다.
3. 질문을 입력하고 **풀이하기**를 누릅니다.
4. 창을 닫으면 앱도 종료됩니다.

첫 캡처 시 macOS 화면 녹음 권한을 요청합니다. 시스템 설정에서 **Offline Lens**를 허용한 뒤 필요하면 앱을 재실행하세요. 이 권한은 스크린샷 한 장을 찍을 때에도 필요합니다. 권한이 없으면 캡처 전에 중단하여 바탕화면만 찍힌 이미지를 정상 결과로 처리하지 않습니다. 캡처는 임시 파일로 만들어 OCR 직후 지우며, 선택한 원본 사진은 수정하지 않습니다. 강제 종료/전원 중단 시에는 임시 캡처가 남을 수 있습니다. 지문과 답변은 앱에서 저장하지 않고, AI 파일 두 개의 경로만 UserDefaults에 저장합니다.

## 모델 없이 가능한 기능

- `4500 ÷ 3`, `(2 + 3) × 4`, 소수와 음수의 사칙연산
- 아래 형식의 영수증에서 가장 많이 구매한 품목의 개당 가격

```text
품목 수량 합계
우유 2 4,800
빵 3 4,500
```

질문: `가장 많이 구매한 물건의 1개 가격은?`

답: `빵: 1개 가격 1500원`

열이 불분명하거나 읽히지 않는 행이 있으면 계산을 거절합니다. 같은 품목의 여러 행은 단가가 일치할 때 합산하며, 최다 수량이 동률이면 모두 표시합니다. 이 첫 버전은 실제 영수증의 모든 레이아웃·할인·세금·반품을 자동 해석하지 않습니다. 필요하면 품목 표만 남겨 수정하세요. OCR은 틀릴 수 있으므로 원본과 대조해야 합니다.

## 국어 지문 등 로컬 AI 연결

**현재 프로젝트에는 AI 모델과 llama.cpp 실행 파일이 포함되어 있지 않습니다.** 따라서 기본 앱만으로 자유로운 국어 지문 풀이를 할 수는 없습니다. 미리 다운로드하거나 다른 기기에서 복사한 다음 두 파일이 필요합니다.

- Apple Silicon용 `llama-cli`와 그 실행에 필요한 동봉 라이브러리
- 800MB 이하의 GGUF 모델. 첫 검증 후보: Qwen3-0.6B Q4_K_M

**AI 파일 설정**에서 실행 파일과 모델을 선택하고 **필요하면 로컬 AI 사용**을 켭니다. 설정만으로 모델을 로딩하지 않습니다. 규칙 계산이 불가능한 질문에만 실행하며, 작업 후 프로세스를 종료하여 모델 메모리를 해제합니다. 런타임 파일은 원래의 동봉 라이브러리와 함께 보관하세요.

런타임은 `--offline`, `--single-turn`, `--no-display-prompt`, `--no-warmup` 등의 옵션을 지원하는 llama.cpp 버전이어야 합니다. 버전별 옵션 변화가 있으므로 실제 모델/런타임 연결 후 호환성 검증이 필요합니다. 앱에는 자동 다운로드나 인터넷 연결 기능이 없습니다. 외부 실행 파일은 신뢰할 수 있는 llama.cpp 배포본을 사용하세요. `--offline`은 런타임 설정이며 임의로 선택한 실행 파일의 네트워크 권한을 OS 차원에서 차단하는 기능은 아닙니다.

## 자원 사용 방침

| 항목 | 설정 |
|---|---|
| 대기 | 화면 감시·반복 타이머·모델 프로세스 없음 |
| OCR | 요청당 한 번, 긴 변 최대 1,800px로 축소 디코딩 |
| 작업 | 직렬 큐에서 한 번에 한 작업 |
| AI CPU | 추론/입력 처리 각 최대 2개 작업 스레드 지정 |
| AI GPU | 모델 레이어 GPU 오프로딩 0 |
| AI 입력 | 지문 1,600자, 질문 200자, 컨텍스트 2,048 토큰 |
| AI 출력 | 최대 256 토큰, 출력 버퍼 64KiB |
| AI 시간 | 최대 60초, 중지 버튼, 앱 종료 시 함께 종료 |
| 발열 | macOS가 serious/critical 상태를 보고하면 AI 시작 거절 |

스레드 제한은 CPU 사용률의 엄격한 상한이 아니고, 모델 파일 크기 제한도 실제 메모리 상한은 아닙니다. Vision의 하드웨어 선택은 OS가 관리합니다. CPU만 사용하는 설정이 모든 작업에서 에너지 효율이 가장 좋은 것은 아니므로 실제 측정 후 조정해야 합니다. 특정 RAM 사용량·배터리 수명·발열 수치는 아직 보장하지 않습니다.

## 검증

```sh
swift test -j 2
sh scripts/build.sh
'.build/release/OfflineLens' --check-ocr
```

계산 테스트는 연산 우선순위, 소수, 0 나눗셈, 잘못된 수식, 동률, 중복 품목, 불분명한 영수증을 다룹니다. `--check-ocr`는 합성 한국어 영수증을 만들어 시스템 OCR과 계산 연결을 확인합니다. 실제 영수증 사진 품질이나 AI 정확도를 보장하는 테스트는 아닙니다.
